# Known-benign places for tools/scan-secrets.sh
#
# Format, one entry per line:
#   path-glob|line-substring|reason
#
# An entry says: this is a placeholder, a setting name, documentation or a test
# fixture, and a human has read the line. The path glob and the line substring
# are both matched case-insensitively, because the names in the code are upper
# case while the prose around them is not.
#
# Every entry below was added after printing the line with its value masked, not
# guessed from the name. Do not add an entry without doing the same.

# --- documentation and examples --------------------------------------------
# The README documents that the licence travels through the environment; no value
# is ever written down.
README.md|wp_cli_update_licence|documentation: names the variable, holds no value
README.md|astra_key|documentation: describes the variable
CHANGELOG.md|astra_key|changelog text about a leak that turned out not to exist
wp-cli-update.conf.example|wp_cli_update_licence|example: placeholder token, no real value
wp-cli-update.conf.example|astra_slug|setting name, not a credential: the add-on slug
wp-cli-update.conf.example|astra_license_command|setting name, not a credential: a wp subcommand
wp-cli-update.conf.example|astra_licence|comment explaining that the key does not belong in this file

# --- script settings --------------------------------------------------------
# ASTRA_SLUG is a public add-on identifier and ASTRA_LICENSE_COMMAND is the name
# of a wp subcommand. MODE_ASTRA is a mode constant. None of them is a secret.
Bash_WP-CLI_Update.sh|astra_slug|setting name, not a credential
Bash_WP-CLI_Update.sh|astra_license_command|setting name, not a credential
Bash_WP-CLI_Update.sh|mode_astra|mode constant
Bash_WP-CLI_Update.sh|licence_file=|path of the hand-over file, not its content
# The help text and the two guard messages tell the operator where the value must
# come from. The value itself is read from the environment or a file.
Bash_WP-CLI_Update.sh|set wp_cli_update_licence or pass --astra-key|help and error text naming the source

# --- tests ------------------------------------------------------------------
# The test proves the licence is neither logged nor placed in argv. The literal
# is deliberately fake and says so in its own name.
tests/test_manager.sh|not-a-real-key|test fixture, obviously not a credential
tests/test_manager.sh|wp_cli_update_licence|test sets the variable to the fixture above
# The scenario suite of branch rewrite-v5.0.0, which is absent from this branch
# but present in the history this guard can walk. The matched value is the public
# add-on slug, passed as a bare argv argument, so the setting rule does not fire.
tests/scenarios/*|astra-addon|test fixture of another branch; the public add-on slug

tools/|scan-secrets|the guard contains pattern definitions, excluded by path anyway
