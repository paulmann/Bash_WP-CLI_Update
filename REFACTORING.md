# REFACTORING — что заимствовано, что изменено и почему

Документ отвечает на три вопроса: какие решения взяты из других конфигураций, что изменено в самом
доноре и от чего сознательно отказались. Каждое утверждение опирается на прогон на общем стенде
(`verify.sh`, 72 проверки) или на статику ShellCheck 0.11.0.

## 1. Заимствования по конфигурациям

| Конфигурация | Что взято | Где это в коде |
|---|---|---|
| **QWEN Hybrid** | правило поиска секретов по **имени**, а не по формату значения; каталог бэкапов `1777`+sticky и дампы `0640`; `--fail-on`; `--max-sites`; `--json-lines`; `--user-env`; идея `--signal`/`--kill-after`; режим отчёта о состоянии | `tools/scan-secrets.sh`, `ensure_dir_for_user()`, `backup_database()`, `final_exit()`, `load_sites()`, `mode_status()`, `run_wp()` |
| **SagaAI DeepSeek Flash** | конфиг как данные: разбор `KEY=VALUE` с белым списком ключей | `parse_config_file()`, `CONFIG_KEYS_RE` |
| **AutoClaw GLM 5.3 Flash + RAGRAF** | маска прав `022` вместо проверки одного ниббла; передача ключа файлом `0600`; `--check`; `--list-modes` | `load_config()`, `licence_open()` |
| **SagaAI DeepSeek Pro + RAGRAF** | маскирование секрета во всех каналах вывода | `redact()` (донор) + `--print-config` |
| **Deepseek Harness Flash** | ядро целиком: 16 режимов, `-j`, бэкапы с ротацией, `--verify`, `--only-active`, `--list-sites`, `--no-user-switch`, `--timeout`, JSON на сайт, `trap`, лок | без изменений |

Порядок работы: донор выбран по критерию «нет дефектов уровня critical и есть все нужные возможности»,
затем в него переносились точечные решения остальных. Никакая часть чужого кода не копировалась
целиком: переносились **идеи и контракты**, реализация написана в стиле донора (табы, `local`,
`declare -a`, `EX_*`-коды, `log_*`).

## 2. Изменения в доноре

| Изменение | Причина | Проверка |
|---|---|---|
| Конфиг парсится, а не сорсится; ключи по белому списку; маска прав `022` | `source` — исполнение кода с привилегиями менеджера, а гвардия смотрела только other-ниббл (HF-04) | конфиги 0620/0660/0664/0666 отвергнуты с rc=2; зонд с `touch` не исполнен |
| Ключ Astra уходит в файл `0600`, в `argv` — результат его чтения | ключ в `argv` виден в `ps` (HF-06) | ключа нет в мок-логе и логах |
| Счётчики воркеров при `-j` | форк терял статистику родителя (HF-02) | `-j 1` и `-j 2` дают одинаковый результат |
| Бэкап вызывается из `core`/`plugins`/`themes`/`db-optimize` | `--backup db` молча ничего не делал вне `--full` (HF-03) | бэкап создаётся во всех четырёх режимах |
| Поисковик запускается `"${BASH}"`, а не через shebang | при `bash` 3.2 в PATH автопоиск падал с rc=4 (HF-01) | поисковик исполнен bash 5.2 при 3.2 первым в PATH |
| `prune_backups` без `mapfile` | `mapfile` не существует в bash 3.2, а матрица поддержки начинается с неё (**HG-01**, найден при портировании) | ротация работает; 5 прогонов с `keep=2` → 2 файла на сайт |
| Каталог бэкапов `1777`+sticky, дампы `0640` | каталог `0750` под root делал выгрузку невозможной для пользователя сайта, а `0640` закрывает дамп с паролями от соседей (**HG-02**) | права проверены на стенде |
| Переносимый таймаут: TERM группе, затем KILL группе | `timeout -k` есть только в GNU; без таймаута зависший `wp` вешает весь парк | зависший мок (8 с) снят за ~1.1 с при `--timeout 1` |
| Новые режимы: `--health`, `--secrets`, ключи `--fail-on`, `--max-sites`, `--user-env`, `--json-lines`, `--signal`, `--kill-after` | закрывают функциональный разрыв с QWEN Hybrid | 6 новых групп проверок в `verify.sh` |
| Версия `6.1.0-hybrid` | версия донора `6.0.0` совпадает с версией другой поставки; две разные поставки с одним номером уже приводили к путанице | `--version` |

## 3. Сознательные отказы

| Отказ | Причина |
|---|---|
| Значения `--user-env` из конфига или `argv` | это канал инъекции в окружение `wp`; принимаются только **имена**, а значения берутся из собственного окружения вызывающего |
| Копирование сканера секретов QWEN как есть | его правило было бы слепым к `define('DB_PASSWORD', …)`, если бы опиралось на форму `NAME=VALUE`; реализация ищет по имени и покрывает обе формы |
| `--fields`, `--page-limit`, `--allow-root auto/always`, `--log-level`, `--lock-file`, `--error-log-file` | интерфейсные удобства: `--log-dir` покрывает сценарий, лок в `TMPDIR` безопаснее произвольного пути |
| Оценка эффективности поставки | замерной сессии у гибрида нет; посторонние средние не подставляются |

## 4. Дефекты, найденные при портировании

| Дефект | Где | Суть | Исправление |
|---|---|---|---|
| **HG-01** | `prune_backups()` | `mapfile` отсутствует в bash 3.2, хотя матрица поддержки начинается с неё: ротация молча не работала на старых хостах | чтение списка в цикле `while IFS= read -r` |
| **HG-02** | `ensure_dir_for_user()`, `backup_database()` | каталог бэкапов создавался `0750` под root, поэтому пользователь сайта не мог записать дамп; файл дампа не имел явного режима | `1777` + sticky, дамп `0640` |

Оба дефекта найдены **до** того, как попали в отчёт: первый — при чтении кода ротации, второй — при
переносе решения QWEN о правах. Ни один из них не проявлялся на macOS-стенде без root, поэтому оба
зафиксированы здесь как найденные анализом, а не прогоном.
