# ANALYSIS — что эта версия делает, чего не делает и чем это подтверждено

Это аудит **итоговой версии**, а не базы. `legacy/ANALYSIS.md` донора описывает состояние базы
`main` (в том числе конфиг через `source`) и оставлен как исторический документ: он верен для базы
и неверен для этой сборки. Ниже — фактическое поведение.

## 1. Режимы

| Режим | Что делает | Изменяет данные | Проверено |
|---|---|---|---|
| `--full` | ядро, плагины, темы, БД, кэш, правила перезаписи; при `-b` — бэкап | да | прогон, rc=0 |
| `--core` | `core update`, `core update-db`, кэш, правила | да | прогон, бэкап создаётся |
| `--plugins` | `plugin update --all`; `--only-active` — только активные с обновлением | да | прогон |
| `--themes` | `theme update --all` | да | прогон |
| `--db-optimize` | `db optimize`, `db repair` | да | прогон |
| `--db-fix` | `db repair` | да | прогон |
| `--cron` | `cron event run --due-now` | да | прогон |
| `--astra` | обновление Astra Pro и активация лицензии | да | прогон, без ключа rc=1 |
| `--verify` | контрольные суммы ядра и плагинов | нет | прогон |
| `--health` | версия ядра, URL, число плагинов, обновления, размер БД | нет | прогон |
| `--secrets` | поиск похожих на секреты значений в конфигурации сайта | нет | прогон, находка → rc=1 |
| `--list-plugins` | инвентарь плагинов, `--fields`, `--page-limit`, `-N` фильтр | нет | прогон |
| `--plugin-manage` | `activate`/`deactivate`/`delete` одного плагина | да | проверка ключей |
| `--list-sites` | список сайтов и выход | нет | прогон, `wp` не вызывается |
| `--check` | окружение и доступность каждого сайта без изменений | нет | прогон |
| `--print-config` | эффективные настройки и слой каждого значения | нет | прогон |
| `--list-modes` | машинный список режимов (18) | нет | прогон |
| `--status` | размеры логов и последние заголовки запусков | нет | прогон |

`--print-config`, `--list-modes` и `--status` работают на хосте **без установленного WP-CLI**:
это диагностика конфигурации, её спрашивают именно тогда, когда ничего ещё не настроено.

## 2. Конфигурация: слои и защита

Порядок приоритета: **командная строка > окружение > файл > значение по умолчанию**.
Файл читается как данные: строка должна иметь вид `KEY=VALUE`, ключ — входить в белый список из 34 имён,
значение не должно содержать обратных кавычек, `$(`, `${`, `|`, `;`, `&`, `<`, `>`.
Нарушение — отказ с кодом **5**, а не «пропустить строку»: молча проигнорированный параметр хуже отказа.

| Проверка | Поведение |
|---|---|
| Маска файла `0620`, `0660`, `0664`, `0666` | отказ, код 2: файл, который может править другая учётная запись, не исполняется |
| Маска `0600`, `0640`, `0444` | принимается |
| Метасимволы в значении | отказ, код 5 |
| Неизвестный ключ | отказ, код 5 |
| `KEY=VALUE` в окружении и в файле | приоритет у окружения, слой виден в `--print-config` |
| Ключ Astra в файле `0600` | файл читается, но **в `argv` процесса `wp` значение не попадает** |

## 3. Безопасность: что закрыто и что осталось

| Угроза | Состояние |
|---|---|
| Инъекция через путь сайта | закрыта: путь передаётся элементом массива, а не строкой команды |
| Инъекция через имя плагина | закрыта: список берётся из `wp plugin list --format=json`, значения не интерполируются |
| Ключ в `argv` | закрыт: ключ уходит в файл `0600`, ребёнок читает его сам |
| Исполнение кода из конфига | закрыто: конфиг парсится |
| Секреты в дампе, доступном соседям | закрыто: каталог бэкапов `1777`+sticky, дамп `0640` |
| Секреты в дереве сайта | обнаруживаются: `tools/scan-secrets.sh` знает и `NAME=VALUE`, и `define('NAME', 'VALUE')` |
| Секрет, разбитый на фрагменты или закодированный в base64 | **не обнаруживается** — заявлено в `--help` сканера |
| Реальная смена пользователя (`runuser`/`sudo`/`su`) | **не проверена на стенде**: нужен root |
| Бинарные файлы в сканировании | пропускаются |

## 5. Известные ограничения

| Ограничение | Номер | Следствие |
|---|---|---|
| `legacy/ANALYSIS.md` описывает базу, а не эту сборку | **HY-01** | читать его как аудит базы, не гибрида |
| Реальная смена пользователя не проверена | — | на стенде нет root; код ветки `runuser`/`sudo`/`su` разобран, но не исполнен |
| Сканер секретов не доказательство отсутствия секретов | — | см. раздел 3 |
| `--signal`/`--kill-after` требуют `perl` (есть на любой целевой системе с WP-CLI) | — | без `perl` и без `timeout(1)` таймаут не работает, и менеджер об этом предупреждает |
| 9 замечаний ShellCheck класса info | **HY-03** | намеренные шаблоны и обработчик через `trap` |
